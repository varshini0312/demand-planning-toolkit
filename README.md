# Demand Planning Toolkit

A statistical demand planning pipeline in Python: outlier cleansing, ABC/XYZ
segmentation, best-fit baseline forecasting, and forecast accuracy and bias
measurement (MAPE, WMAPE, Bias %, MAD).

Built to mirror how a planning organisation actually runs a forecast cycle —
generate a statistical baseline, measure it honestly against actuals, segment
where accuracy matters, and push the exceptions to a planner instead of asking
them to review everything.

All data here is synthetic and generated by `generate_sample_data.py`.

---

## The pipeline

```
sales history
  -> outlier cleansing          modified z-score (MAD), replace not delete
  -> ABC / XYZ segmentation     revenue contribution x demand variability
  -> best-fit baseline          6 models backtested per series, winner selected
  -> accuracy and bias          MAPE, WMAPE, Bias %, MAD by segment and series
  -> exception report           series that miss target AND show persistent bias
```

## Running it

```bash
pip install -r requirements.txt
python generate_sample_data.py          # 11,484 rows: 60 items x 8 locations x 36 months
python run_pipeline.py                  # full cycle, writes to output/
python run_pipeline.py --holdout 6 --horizon 6 --target-wmape 30
```

That output tells a planning story rather than just printing numbers:
accuracy degrades cleanly from AX to CZ as demand gets more erratic, and there

tracked separately from error size.

## Why these metrics

| Metric | What it answers |
|---|---|
| **MAPE** | Average percentage error. Readable, but distorts on near-zero demand |
| **WMAPE** | Volume-weighted error. The reporting default — big items carry proportionate weight |
| **Bias %** | *Which way* the forecast is wrong. Persistent bias builds excess stock or stockouts |
| **MAD** | Error in units, for conversations about inventory cover rather than percentages |

20% WMAPE with 0% bias and 20% WMAPE with −18% bias are completely different
problems. Only one of them quietly drains working capital.

## Design decisions

**Baselines in numpy, not a forecasting library.** These are the numbers a
planner overrides in a consensus cycle, so being able to explain exactly what
the forecast is and why it moved matters more than model sophistication. The
six models — naive, 3- and 6-month moving average, seasonal naive, simple
exponential smoothing, Holt linear trend — cover what most statistical
baselines in a planning system actually use.

**Best fit is backtested, not assumed.** Each series is scored on a holdout and
the winning model is selected on weighted MAPE, so near-zero months cannot
dominate selection. The model mix is reported, because "everything picked
naive" is itself a finding about the data.

**Outliers are replaced, not deleted.** A one-off bulk order or a data-entry
spike shouldn't set the level for the next six months, but deleting the row
breaks the time series. The modified z-score (median absolute deviation) is
used instead of a standard z-score because the spikes being hunted inflate the
mean and standard deviation, hiding themselves.

**Segmentation before targets.** A single accuracy target across a whole
portfolio is meaningless. AX items deserve a tight baseline and a demanding
target; CZ items are intermittent and erratic, and chasing accuracy there wastes
planner time. The grid is what makes the target defensible.

## Files

```
generate_sample_data.py   synthetic history with trend, seasonality, promos, outliers
cleansing.py              modified z-score outlier detection and replacement
segmentation.py           ABC (revenue share) and XYZ (coefficient of variation)
forecasting.py            six baseline models, backtesting, best-fit selection
accuracy.py               MAPE / WMAPE / Bias % / MAD, target and bias flagging
run_pipeline.py           orchestration and reporting
```

Output: `forecast.csv`, `accuracy_by_segment.csv`, `exceptions_for_review.csv`.

## Possible extensions

- Causal enrichment: promotional uplift, price elasticity, weather and calendar effects
- Lag-based accuracy (M-1 / M-2 / M-3) to show how the forecast converges as the month approaches
- Forecast value added (FVA): does planner adjustment actually beat the statistical baseline?
- Safety stock and reorder point derived from forecast error distribution
